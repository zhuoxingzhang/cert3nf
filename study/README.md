# The human-designer study

Software and materials of a study in which database designers answer the questions of Cert3NF.
Each participant answers, in each of two sessions, a fixed block of 18 questions about one relation and then the questions that the tolerant mode of Cert3NF (`confirm/v5tol.py`, mechanism c) asks live, up to 100 questions or 40 minutes.
Three conditions: E (an expert who studied the relation's documentation), P (a practitioner who reads it in the session) and U (a practitioner without it); three relations, R1 `ssb_customer`, R2 `tpcds_core` and R3 `fresh_abs_mb`; participant 01 of each condition does R1 then R2, 02 does R2 then R3, and 03 does R3 then R1.

## Layout

| path | content |
|---|---|
| `code/server.py`, `code/index.html`, `code/ui.html` | the web site: a start page where a participant enters their code and session, several participants at once, a try for anyone, `/status` for the experimenter, `/healthz` for an uptime monitor |
| `code/session.py` | one session: the block, the live questions, filler questions so that a question asked again is at least three questions apart, the exit questionnaire; resumes from its file after a restart |
| `code/v5study.py` | `confirm/v5tol.py` with a hook for a person (don't know, stop), generated by `code/make_v5study.py` |
| `code/store.py` | copies the session files to a private GitHub repository |
| `code/replay.py` | recomputes the method's output of a session from its answers |
| `blocks/` | the fixed blocks (`block_<relation>.json`, with a review file listing each question's truth and its derivation) and `supplement.json`, two FDs of `fresh_abs_mb` that hold in the domain but are missing from the documentation |
| `prebuilt/` | each relation, its data and its advisor, built by `code/build_kit.py` |
| `docs/` | the documentation shown to E and P |
| `materials/` | the instructions with two practice questions, the exit questionnaire and the debrief |

## Running the study

Locally: `python study/code/server.py`; session files are written to `study/sessions/`, which never enters this repository.

Online: `render.yaml` describes a free Render web service.
There are no passwords: a participant opens the site, enters the code of the invitation (E01 to U03) and the session number, or opens `/s/<code>/<session>/` directly, and reopening it continues the session.
Codes starting with T are tests that are not part of the study, and "Try it" on the start page opens a try of its own whose files are not kept.
`/status` lists every session's state and number of answers, never the answers themselves.
A free instance sleeps after 15 minutes without a request, so an uptime monitor requests `/healthz` every 5 minutes.
Its disk is wiped at every restart, so the answers are kept by setting `STUDY_GITHUB_REPO` (a private repository) and `STUDY_GITHUB_TOKEN` (a fine-grained token with Contents read and write on that repository only).
The server puts every changed session file there every 10 seconds, fetches them at startup, and continues an interrupted session by replaying its answers.
Until both are set, the status page warns that storage is not durable.
Pushing changes to the files listed in `render.yaml` redeploys the service and interrupts running sessions briefly.

## Building and checks

`build_kit.py` builds `prebuilt/` from a folder with the method and all its inputs, including the LLM answers, which are not in this repository (`STUDY_SOURCE`, see `code/common.py`); it first checks that the modules imported here have the same code as there.
The advisor's prior is trained on the other relations, which needs about 530 MB; a session on the server needs a few MB.

```bash
python study/code/test_session.py             # answer modes, replay, resume after a cut, six sessions at once
python study/code/test_session.py --compare   # the same sessions here and with the method built from STUDY_SOURCE
python study/code/test_store.py               # storage against an imitation of the GitHub API
python study/code/replay.py study/sessions/E01_s1_ssb_customer.jsonl
```

`check_v5study.py` (run in `STUDY_SOURCE`) checks that `v5study.py` equals `v5tol.py` field for field when nobody answers "don't know" or stops; `check_full.txt` and `check_sure.txt` are its output.
